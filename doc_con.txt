# ANSYS AI-Powered Automated Technical Report Generation Platform

## Project Overview

### Problem Statement

Engineering organizations spend significant time manually creating simulation reports after completing analysis in ANSYS Workbench. While ANSYS provides report generation capabilities, the generated reports often require substantial manual effort to:

* Export and organize simulation images
* Insert images into company-specific templates
* Copy numerical results
* Include design calculations from Excel sheets
* Write engineering observations and conclusions
* Generate executive summaries
* Maintain document formatting standards

For complex projects involving multiple analyses such as Static Structural, Modal, Harmonic Response, Random Vibration, CFD, and MBD, report preparation can consume several hours per simulation iteration.

---

## Project Objective

Develop an intelligent report automation platform that automatically extracts simulation results, images, and engineering data from ANSYS Workbench projects and generates client-ready Word and PDF reports following predefined company templates.

The system should reduce report generation time from several hours to a few minutes while ensuring consistency and accuracy.

Module 1 — ANSYS Data Extraction
This is the hardest and most critical piece. Use PyAnsys (Ansys's official Python SDK):

ansys-mechanical-core to connect to a running Mechanical instance and query the project tree
ansys-dpf-core to read result files (.rst) directly — stress, strain, deformation, frequencies — without needing the GUI open
Use Mechanical.run_python_script() to trigger ACT scripting for things DPF can't reach

Practical approach: Open Mechanical, use its scripting console to prototype what data you need, then replicate that in Python via ansys-mechanical-core. DPF is better for bulk result extraction since it reads .rst files offline.

Module 2 — Image Export
ANSYS's scripting API can export images, but quality is inconsistent. Two approaches:

Inside Mechanical: ExtAPI.Graphics.ExportImage(path, format, settings) — works but is limited
Better approach: Use DPF's result data + pyvista or matplotlib to render your own high-quality contour plots from the raw mesh + result arrays. You get full control over resolution, color maps, and annotations.

For mesh and geometry screenshots, Mechanical scripting remains the most straightforward path.

Module 3 — Excel Integration
Simplest module. Use openpyxl to read named ranges or specific cells:

Build a structured dict of parameters, then pass it downstream to both the AI engine and the template renderer.

Module 4 — AI Analysis Engine
Use the Anthropic API (Claude) or OpenAI. Feed it structured JSON of results:

Recommended Build Order
Start with this sequence to get value early and validate assumptions:

Proof of concept: Extract one result (e.g. max stress) from a known .rst file using DPF → print it. This tells you if the ANSYS integration is feasible.
Static report: Hard-code some results, populate a Word template, export PDF. Validate the template system.
Image pipeline: Get one good contour plot out of PyVista from DPF data.

The document is written as a product requirements document (PRD) — it's the "what" and "why", not the "how". It defines what each module should do (extract this data, export these images, generate these narratives) but leaves the implementation decisions to the engineering team.
